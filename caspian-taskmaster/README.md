# caspian-taskmaster

Public assets for [Caspian Taskmaster](https://marketplace.visualstudio.com/items?itemName=CaspianTools.caspian-taskmaster), the issue tracker that lives inside VS Code. The source repository is private, so everything the public needs to see is here.

| Folder | Contents | Linked from |
|---|---|---|
| [`screenshots/`](screenshots/) | README / store-listing screenshots | the extension's `README.md`, so the VS Code Marketplace, Open VSX and VS Code's extension page |
| [`release-notes/`](release-notes/) | one Markdown file per release, plus an [index](release-notes/README.md) | the release process (replaced GitHub Discussions announcements from 1.31.2) |

## Screenshots

```
screenshots/
├── <X.Y.Z>/              ← one folder per screenshot refresh, named after the release that introduced it
│   ├── dark/             ← Default Dark Modern theme
│   │   └── <view>.png    ← 3200×2000, e.g. board.png, table.png, issue-claude.png
│   └── light/            ← Default Light Modern theme, same filenames
└── *.png                 ← original flat set, still linked by 1.31.2 — do not remove
```

| Set | Views |
|---|---|
| [`1.31.3/`](screenshots/1.31.3/) | `board`, `table`, `issue-details`, `issue-dependencies`, `issue-comments`, `issue-logs`, `issue-claude`, `new-issue`, `filters`, `sprints`, `settings`, `metrics`, `sidebar` |

The sets are generated by `npm run screenshots` in the extension repo. It drives the real extension against a fictional demo project, so the images contain no real user data. A refresh goes into a **new** `<X.Y.Z>/` folder. Never overwrite an existing set, because released versions keep linking to it.
