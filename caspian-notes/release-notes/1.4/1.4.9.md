# Caspian Notes 1.4.9: Sync tells you when it needs a reconnect

caspiantools.com now ties each VS Code pairing to one workspace and lets it run for 180 days. When a pairing expires, Caspian Notes says so once and offers a Reconnect button, instead of failing quietly in the log every 15 seconds.

- 🔔 One notification, one button: **Reconnect** reopens the pairing flow
- 🔒 A pairing opens only the workspace you picked, and only your notes there
- 🛡️ A dependency used to read note front matter received a security update

Your notes stay yours: local first, synced only when you say so.

https://marketplace.visualstudio.com/items?itemName=CaspianTools.caspian-notes

## Full changes

### Changed
- **Sync stops and asks you to reconnect when caspiantools.com refuses the pairing, instead of retrying forever.** caspiantools.com now scopes the VS Code pairing token to the workspace you picked and expires it 180 days after pairing (pairings made before this change keep working until 2027-02-01, then need a reconnect too). Before, an expired or out-of-scope pairing made both sync loops fail every 15 seconds in the log with no visible sign. Now two consecutive `PERMISSION_DENIED` results stop the engine, set the last error to a plain explanation, and show one notification with a **Reconnect** button that runs *Caspian Notes: Connect*. `THREAT_MODEL.md` §G records the narrower blast radius of a stolen refresh token.

### Security
- **`js-yaml` 3.15.1 → 3.15.2** under `gray-matter` (production dependency), clearing GHSA-5p4m-2wfm-xmqj / GHSA-2883-xcg3-v3hh (quadratic CPU on crafted YAML). Only the lockfile moved; the audit is clean again.
