# Caspian Office 1.231.1: A way around sites that refuse to be framed

Some sites tell browsers never to show them inside another page, so the Mobile view tester's frame stays blank. A separate window is not a frame, and now the tester opens one for you at the device's exact size.

- **New — Open in a window sized like the device.** In URL mode every frame has a window button that opens the address in a popup matching that device's width and height, so the page's media queries respond exactly as they would in the frame.
- **Fixed — Our own frame policy no longer flags the tester.** Loading a URL used to log a Content Security Policy warning from our side on every page; it no longer does.
- **Fixed — Workspace install meta.** Chrome stops warning about the deprecated Apple-only tag in the installed app.

Preview a page at real device widths, in a frame or in a window, all in your browser.

## Full changes

### Added
- **Open the page in a window sized like the device.** Sites that send X-Frame-Options or a frame-ancestors policy show Chrome's "refused to connect" page inside the frame, and no browser can get around that. A separate window is not a frame, though: in URL mode every frame in the Mobile view tester now carries a window button that opens the address in a popup exactly that device's size, so the site's media queries respond the same way. The FAQ explains it, and how to allow the tester on a site you own.

### Fixed
- **Our own frame policy no longer flags the tester.** The site's report-only Content-Security-Policy listed only our origin under frame-src, so every URL loaded in the tester logged a violation and would have been blocked the day that policy is enforced. It now allows any http(s) address.
- **Workspace install meta.** The Workspace page now carries the standard mobile-web-app-capable tag beside the Apple one, so Chrome stops warning about the deprecated form.
